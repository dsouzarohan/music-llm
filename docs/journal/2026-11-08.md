baseline. Run directory: `data/runs/20261107-125445-baseline-186m/` on Drive (`metrics.jsonl` and

## Setup

- `configs/colab-186m-jan2026.toml`: 186,426,284 params (24L, 768, 12 heads, context 2048,
  vocab 3500), dropout 0.1, batch 128, lr 1e-4 OneCycle, 50 epochs × 2000 windows.
- **micro_batch_size 4 instead of 8.** Colab gave an A100-SXM4-**40GB**; the journal's earlier
  runs had the 80 GB card (61 GB used at micro-batch 8, 2025-12-03). The effective batch is still
  128 (32 × 4), so the optimisation is the same.
- torch 2.14.1+cu130, Python 3.13, bf16 autocast, `torch.compile`.
- Val: the new fixed val set, 512 non-overlapping windows evenly spaced over 3,365 val files.

## Where the compute goes (eager profile, micro-batch 2, 10 steps)

- MFU **1.7%** in eager mode vs **12.8%** compiled: `torch.compile` alone is ~7.5×.
- The GPU ran kernels for 4.25 s of a 13.4 s wall window: **busy 32%**. The rest is the GPU
  waiting on Python to launch kernels (12 heads × 24 layers in a Python loop).
- Attention forward is **38%** of all device kernel time, ~30× the MLP forward.
- Matmuls (`mm` + `bmm`) are only ~23% of kernel time. Copies and dtype casts (`aten::copy_`/`to`,
  bf16↔fp32 around the manual softmax) are 31%, the rest is masking, padding, softmax and
  elementwise ops: memory-bound attention plumbing.
- At micro-batch 8, eager **and** compiled both ran out of 40 GB: every head keeps several
  (B, 2048, 2048) score tensors for backward.

These are Phase 2's targets: fused SDPA/FlashAttention (no T×T matrix in memory), all heads in
one batched op, and a KV cache for generation.

## What broke along the way

- **Drive was too slow to train from**: ~0.2 MB/s reading 20k small files through the mount (a
  network round trip each). `scripts/colab.sh setup` now stages `tokenized/` to local disk with
  64 parallel copies: 62 s.
- **Launcher bugs**: `a && b & c` backgrounds the whole chain and held the exec pipe open; Python
  buffered stdout so the log was empty. Fixed with `{ nohup … & }` and `python -u`.
- **The first attempt's VM was terminated after ~80 min** (epoch 14) while no browser tab was
  attached. The rerun kept the session open in a tab and finished.
- **Drive uploads asynchronously**: `metrics.jsonl` had synced through epoch 14, but the 6.7 GB
  `best.pt` writes from epochs 10–14 hadn't, so the resume started from epoch 9.
- **Two resume bugs only a GPU could show**: the saved RNG state was mapped to CUDA and
  `torch.set_rng_state` rejected it; and the checkpoint stayed on the GPU for the whole run
  (~2.2 GB), which pushed micro-batch 4 over 40 GB. Both fixed with regression tests.
- **Exact resume, confirmed in production**: the resumed run re-trained epochs 10–14 and got
  val 4.5107 / 4.4404 / 4.3653 / 4.2916 / 4.2449, matching the first attempt's
  4.5107 / 4.4404 / 4.3653 / 4.2916 / 4.2450.
- **Checkpoints are 6.7 GB**, 4.8 GB of it the per-head causal-mask buffers (known issue #26).
  `save_every = 5` wrote ~80 GB to Drive.
- Some val token files are empty (known issue #16), which crashed sampling until it filtered by
  length; and some filenames contain newlines, which makes `ls | wc -l` miscount.

All of these are in `docs/colab.md` under "Gotchas". The Colab CLI itself was flaky late in the
session (dropped exec connections, read timeouts); `colab console` was the reliable fallback.
