The next thing to do was to implement a learning rate scheduler, an inbuilt PyTorch tool that helps maintain the learning rate to ensure we don’t make big updates to the parameters

The scheduler is called [OneCycleLR](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.OneCycleLR.html)

While that itself didn’t help, what kinda helped was to increase our batch size from 64 to 128, to encourage gradient stabilization by smoothing out noise in the gradients, smaller batches tend to be more noisy. Larger the batch size, more you represent your overall data in one batch. 128 seemed to the sweet spot to ensure we don’t hurt generalization. Important to note here is that the micro batch size is still 16, as I’m limited by VRAM (yes, on an A100), so 8 accumulation steps in a single batch. Finally, we used a lower max learning rate of 1e-4.

But still, we had an explosion again, at epoch 24, validation jumped from 4.34 to 5.34 (perplexity from 77 to 209)

This could be because of the scaling we do in the RelativeAttentionHead

As of now, we are adding he relative bias (computed for musical distances) after scaling the content scores

```python
scores = q @ k.transpose(-2, -1)
scores = scores * (self.head_size ** -0.5) # Scale content down
scores = scores + bias                     # Add unscaled bias (Huge!)
```

Since we are dividing $`Q \cdot K^T`$ by $`\sqrt{d}`$ ($`{d}`$ is embedding dimensionality divided by number of heads = 768/12 = 64), so $`\sqrt{64}=8`$, but not the bias, our relative position embeddings are 8x stronger than the content attention. As the model trains, these bias weights grow, eventually causing an explosion where the model only cares about position and ignores content.

We can fix this by doing

```python
content_scores = q @ k.transpose(-2, -1)
# Add bias first (so both are raw dot products)
scores = content_scores + bias 
# Then scale everything
scores = scores * (self.head_size ** -0.5)
```

- Update the `clip_grad_norm_` value to `0.5` to tighten clipping
- Add resume logic to `train.py` to be able to resume from the `best.pt` we recorded from the current training run
- Some architectural model changes for better activations and normalizations (**cannot** be done in between of training) 
    - GeLU activation function instead of ReLU (standard for transformer architectures)
    - **Base Init:** `Normal(0, 0.02)` instead of PyTorch default (Kaiming uniform).
    - **Residual Init:** Scale output projections by $`1/\sqrt{2L}`$. This is the "magic trick" that allows GPT models to train deep without exploding.
